# 서브에이전트 호출 프롬프트 패턴

자주 쓰는 서브에이전트 호출 시 프롬프트 구성 패턴 모음.
에이전트는 컨텍스트를 공유받지 않으므로 **Self-contained 원칙**으로 작성한다.

> **Self-contained 원칙**: 에이전트 프롬프트는 현재 대화를 모르는 동료에게 브리핑하듯 작성한다.
> 목표·배경·제약·결과 형식을 모두 명시한다.

---

## `[서비스명]-dev` — 기능 구현 위임

```
[작업 목표]
<서비스명> 프로젝트에서 <기능명>을 구현한다.

[배경]
- 현재 브랜치: <브랜치명>
- 관련 이슈: #<번호>
- 구현 이유: <간단한 배경 1~2줄>

[작업 시작 전 필수]
1. `<docs 경로>/status/HANDOFF_NOW.md` 를 먼저 읽는다.
2. 유사 기능 파일 최소 2개를 확인해 기존 패턴을 파악한다.
   - 참고 파일 1: <파일 경로>
   - 참고 파일 2: <파일 경로>

[구현 사양]
- <사양 1>
- <사양 2>
- <사양 3>

[제약]
- 커밋은 하지 않는다.
- 기존 파일 구조·스타일을 따른다.

[완료 기준]
- 변경 파일 목록과 주요 변경 내용 요약 출력
```

## `[서비스명]-dev` — 버그 수정 위임

```
[작업 목표]
<서비스명>에서 발생하는 <버그 현상>을 수정한다.

[버그 재현 경로]
1. <화면/URL>에서
2. <동작>을 하면
3. <기대 결과> 대신 <실제 결과>가 발생

[의심 파일]
- <파일 경로 1> — <의심 이유>
- <파일 경로 2> — <의심 이유>

[참고]
- 생성 화면 vs 수정 화면 동일 기능 구현체를 비교해 원인을 좁힌다.
- 수정 범위는 최소로 유지한다. 주변 코드 리팩토링 금지.

[제약]
- 커밋은 하지 않는다.
- 수정 후 변경 파일 목록·원인·수정 내용 요약 출력
```

## `doc-writer` — HANDOFF 갱신 위임

```
[작업 목표]
오늘 세션의 작업 내용을 바탕으로 HANDOFF 문서 3종을 갱신한다.

[오늘 세션 요약]
- 브랜치: <브랜치명>
- 이슈: #<번호>
- 변경 파일: <파일 목록>
- 주요 변경: <1~3줄 요약>
- 다음 할 일: <미완료 작업>

[갱신 대상 (순서 준수)]
1. `<docs경로>/status/HANDOFF_NOW.md`
   - §1 현재 상태 갱신 (브랜치·이슈·빌드 명령)
   - §2 다음 작업 갱신 (미완료 작업이 첫 번째로)
   - 60줄 이하 유지
2. `<docs경로>/history/세션_노트.md`
   - 최상단에 `> Session note YYYY-MM-DD: [1~2줄 요약]` prepend
3. `<docs경로>/plans/HANDOFF.md`
   - `## Session Update YYYY-MM-DD` 섹션을 최상단에 추가
   - 변경 파일·주요 변경·다음 할 일 포함

[검증]
- HANDOFF_NOW.md §2 첫 항목이 가장 급한 다음 작업인지 확인
- HANDOFF_NOW.md 60줄 이하인지 확인
```

## `code-reviewer` — PR 리뷰 위임

```
[작업 목표]
아래 변경 사항에 대해 독립적인 코드 리뷰를 수행한다.

[변경 파일]
<git diff 출력 또는 파일 목록>

[리뷰 기준]
- 기존 아키텍처 패턴 준수 여부
- API 레이어 경유 여부 (직접 fetch 금지)
- 보안 취약점 (XSS, SQL Injection, 하드코딩 시크릿 등)
- 타입 안전성
- 누락된 예외 처리

[결과 형식]
- 심각도별(🔴 차단 / 🟡 권고 / 🟢 칭찬) 항목으로 정리
- 200자 이내로 간결하게
```

```
[에러 정보]
- 에러 메시지: <에러 전문>

- 발생 조건: <재현 경로>

[시도한 것]
- <시도 1>: <결과>
- <시도 2>: <결과>

[결과 형식]
- 원인: <한 줄>
- 근거: <파일·라인 근거>
- 수정 방향: <구체적 수정 지점과 방법>
```

## `[마스터 에이전트명]` — 크로스 프로젝트·장기 작업 위임

```
[작업 목표]
<작업 설명>. 여러 프로젝트 / 패키지에 걸친 작업이므로 마스터 에이전트 경유.

[배경]
- 관련 프로젝트: <프로젝트 A>, <프로젝트 B>
- 관련 이슈: #<번호>
- 이유: <크로스 프로젝트인 이유 한줄>

[작업 범위]
- <프로젝트 A> 에서 할 것: <내용>
- <프로젝트 B> 에서 할 것: <내용>

[우선순위]
<프로젝트 A> → <프로젝트 B> 순서로 진행.

[제약]
- 커밋은 하지 않는다.
- 각 프로젝트의 HANDOFF_NOW.md를 먼저 읽고 시작한다.
- 변경 완료 후 영향 범위 요약 출력
```
