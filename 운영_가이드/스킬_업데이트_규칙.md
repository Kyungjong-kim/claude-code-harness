# 스킬 업데이트 규칙

## SoT — 전역이 원본이다

| 위치 | 역할 |
|------|------|
| `~/.claude/skills/` | **운영 SoT.** 실제로 실행되는 원본. 실경로·실서비스명 포함 |
| `하네스/skills/` | OSS 배포 스냅샷 (프로젝트 스킬) — 마스킹 적용본 |
| `하네스/personal-skills/` | OSS 배포 스냅샷 (개인 생산성 스킬) — 마스킹 적용본 |

**수정은 항상 전역에서 한다.** repo 사본을 직접 고치면 전역과 어긋난다.

## 전파는 단순 복사가 아니다

repo 사본은 **공개 배포물**이므로 전역 원본을 그대로 `cp`하면 개인 경로·사내 식별자가 유출된다.
전파는 반드시 **복사 → 마스킹 치환 → 검증** 3단계를 거친다.

### 마스킹 대상

| 전역 원본 | 배포 스냅샷 |
|---|---|
| 개인 노트·업무 소스 절대경로 | `<개인_노트_경로>` / `<업무_소스경로>` |
| 사내 서비스명·프로젝트명 | `<프로젝트>` / `<서비스명>` |
| 계정·이메일·워크스페이스 ID | 플레이스홀더 |
| GitHub 조직명 (`github.com/<org>/...`) | `<조직>` |

### 절차

```bash
SKILL=<스킬명>
SRC=~/.claude/skills/$SKILL/SKILL.md
DST=<하네스폴더>/personal-skills/$SKILL/SKILL.md   # 프로젝트 스킬은 skills/

cp "$SRC" "$DST"
# 마스킹 치환 (경로·서비스명 — 스킬마다 대상 다름, 아래 검증으로 확인)
${EDITOR:-vi} "$DST"

# 검증 — 하나라도 잡히면 배포 금지
# 검증 패턴은 공개 저장소에 사내 식별자를 적지 않기 위해 별도 파일로 분리한다.
# ~/.claude/masking-patterns.txt 에 1줄 1패턴으로 실제 식별자를 보관(로컬 전용).
grep -nEf ~/.claude/masking-patterns.txt "$DST" && echo "🔴 유출 — 치환 미완" || echo "✅ 통과"

# 최소 공통 패턴(식별자 없이도 잡히는 것)
grep -nE '/Users/|CloudStorage|@[a-z0-9.-]+\.(ai|com)|[가-힣]{2,4}\s?(님|씨)?\s?\(git' "$DST"
```

배포 스냅샷에는 **설치 안내 문구**를 남긴다 — 플레이스홀더를 실제 값으로 바꿔야 동작한다는 사실을 사용자가 알아야 한다.

```markdown
> ⚠️ **설치 후 필수**: 이 파일의 `<개인_노트_경로>`를 실제 노트 경로로 교체해야 정상 동작한다.
```

## 전파 시점

기능을 고친 그 세션에 함께 전파한다. **미루면 어긋난다** — 2026-04~06 사이 전역에서 개선된
`daily-note`가 배포 스냅샷에 2개월간 반영되지 않아, 두 사본이 서로 다른 동작을 기술하는 상태가 됐다.

전파를 미룰 거면 최소한 배포 스냅샷 상단에 `<!-- 전역 대비 미반영: YYYY-MM-DD -->`를 남긴다.
