# HANDOFF 문서 유지 규칙

> **적용 범위 — HANDOFF 3종 체계를 쓰는 프로젝트 한정 (2026-08-19 명시).**
> 개인 repo(`~/projects/*`)는 세션 인계를 **GitHub 이슈·커밋**으로 하며 이 규칙을 적용하지 않는다.
> 규칙만 복사하고 갱신하지 않으면 문서와 실행이 어긋나 나머지 규칙의 구속력까지 떨어진다.

HANDOFF_NOW.md · HANDOFF.md · 세션_노트.md 3종 문서의 비대화 방지 및 아카이브 기준.

---

## 문서별 역할과 크기 한도

| 문서 | 역할 | 크기 한도 | 초과 시 |
|------|------|-----------|---------|
| `HANDOFF_NOW.md` | 현재 상태 핫 문서 — 세션 시작 시 첫 번째로 읽힘 | **60줄 이하** | 오래된 §2 항목을 HANDOFF.md로 이관 |
| `세션_노트.md` | 세션 1~2줄 요약 누적 | **30일치** | 30일 이상 항목을 `history/HANDOFF_archive_YYYY.md`로 이관 (월별 갱신) |
| `HANDOFF.md` | 세션 변경 이력 누적 | 제한 없음 | 월초에 전월 Session Update 전체를 `plans/HANDOFF_archive_YYYY.md`로 이관 |

## HANDOFF_NOW.md 갱신 규칙

### §1 현재 상태

세션 시작 전 항상 현재 상태를 반영해야 한다.

```markdown
## §1 현재 상태

- **브랜치**: `<타입>/<이슈번호>`
- **이슈**: #<번호> — <이슈 제목>
- **빌드**: `<빌드 명령>`
- **마지막 작업**: <날짜> — <한줄 요약>
```

**갱신 필수 시점:**
- 브랜치 전환 시
- 새 이슈 시작 시
- 빌드 명령 변경 시
- 세션 종료 시

### §2 다음 작업

항상 "가장 급한 것이 첫 번째"를 유지한다.

```markdown
## §2 다음 작업

1. 🔴 <최우선 할 일> — <간단한 이유>
2. 🟡 <다음 할 일>
3. 🟢 <여유 있는 작업>
```

**항목 이관 기준:**
- 완료된 항목 → 즉시 삭제
- 2주 이상 미착수 항목 → `⏸` 태그 추가 후 §2 하단으로 이동 (60줄 초과 시 HANDOFF.md로 이관)
- 60줄 초과 시 → §2 하단 항목부터 HANDOFF.md로 이관

## 세션_노트.md 갱신 규칙

### 형식

```
> Session note YYYY-MM-DD: [1~2줄 요약. 변경 내용 + 다음 연결점]
```

### 작성 기준

- 최신 세션이 항상 **파일 최상단**에 위치
- 1~2줄 이내 (길면 HANDOFF.md에서 확인하도록)
- 날짜는 `YYYY-MM-DD` 형식 고정

### 아카이브 기준

30일 이상 지난 항목은 월별로 아카이브한다.

```bash
# 아카이브 예시 (30일 이상 항목을 별도 파일로 이관, 월별 갱신)
# history/HANDOFF_archive_2026.md 에 이관 후 세션_노트.md에서 삭제
```

## HANDOFF.md 갱신 규칙

### 새 세션 섹션 추가 형식

```markdown
## Session Update YYYY-MM-DD

### 변경 파일
- `<파일 경로>` — <변경 내용 한줄>

### 주요 변경
- <변경 1>
- <변경 2>

### 다음 할 일
- [ ] <미완료 작업 1>
- [ ] <미완료 작업 2>
```

**규칙:**
- 새 섹션은 파일 **최상단**에 prepend (최신이 위)
- 기존 섹션은 건드리지 않는다

## agent/ 문서 갱신 규칙

`docs/<서비스명>/agent/` 하위 문서는 프로젝트 구조가 바뀔 때 함께 갱신한다.
HANDOFF 3종과 달리 매 세션마다 갱신하지 않고 **변경 트리거** 기준으로 갱신한다.

> agent/ 문서는 `/project-init`이 자동 생성하는 에이전트 컨텍스트 파일이다.
> 작성 양식은 [Claude Code/템플릿/agent_문서_템플릿.md](../Claude%20Code/템플릿/agent_문서_템플릿.md) 참조.

| 문서 | 갱신 트리거 |
|------|------------|
| `agent/architecture.md` | 새 패키지 추가, 레이아웃 구조 변경, 인증 방식 변경, 상태관리 도구 교체 |
| `agent/conventions.md` | 린터·포매터 설정 변경, 파일 네이밍 규칙 변경, 새 컨벤션 팀 합의 시 |
| `agent/design-system.md` | 디자인 토큰 추가·변경, 컴포넌트 라이브러리 업그레이드 |

**갱신 방법**: `doc-writer` 에이전트에게 위임. 변경된 소스 파일과 변경 내용을 전달한다.

```
[작업 목표]
<서비스명>/docs/agent/architecture.md를 최신 소스 구조에 맞게 갱신한다.

[변경 내용]
- <변경된 것 설명>

[갱신 기준]
- 핵심 4가지(앱 종류·레이아웃·인증·상태관리)만 기재
- 상세 내용은 ../architecture/ 문서로 이관
- 에이전트가 작업 시작 시 읽는다는 점을 고려해 간결하게 유지
```

## 비대화 방지 체크리스트

세션 종료 시 아래 항목을 확인한다.

```
- [ ] HANDOFF_NOW.md §1 현재 브랜치·이슈가 맞는지
- [ ] HANDOFF_NOW.md §2 첫 항목이 가장 급한 다음 작업인지
- [ ] HANDOFF_NOW.md 60줄 이하인지
- [ ] 세션_노트.md 최상단에 오늘 날짜 요약이 있는지
- [ ] HANDOFF.md 최상단에 오늘 Session Update가 있는지
- [ ] 완료된 §2 항목이 남아 있지 않은지
```

## 자주 발생하는 문제

| 증상 | 원인 | 조치 |
|------|------|------|
| HANDOFF_NOW.md가 100줄 이상 | §2 항목을 삭제하지 않고 계속 추가 | 완료 항목 삭제, 보류 항목 HANDOFF.md 이관 |
| §2 첫 항목이 2주 전 작업 | 우선순위 갱신 누락 | 현재 가장 급한 작업으로 순서 재정렬 |
| 세션_노트.md에 오늘 날짜 없음 | 세션 종료 절차 미실행 | `doc-writer` 에이전트로 갱신 위임 |
| HANDOFF.md에 Session Update 없음 | STEP 3 절차 건너뜀 | CLAUDE.md STEP 3 순서대로 재실행 |
