## 패턴 1 — 신규 기능 구현

```
[세션 시작]
  → HANDOFF_NOW.md 읽기
  → 이슈 번호 확인 (없으면 이슈 생성 먼저)
  → 브랜치 생성: git checkout develop && git pull && git checkout -b task/<번호>

[작업]
  → [서비스명]-dev 에이전트에 기능 구현 위임
    (프롬프트: 목표 + 참고 파일 2개 + 사양 + "커밋하지 말 것")

[검증]
  → 빌드 확인: <빌드 명령>
  → 필요 시 playwright-validator로 UI 동작 확인

[세션 종료]
  → doc-writer 에이전트에 HANDOFF 3종 갱신 위임
  → 커밋은 사용자가 "커밋해줘" 요청 시에만
```

## 패턴 2 — 버그 수정

```
[세션 시작]
  → HANDOFF_NOW.md 읽기
  → 버그 이슈 번호 확인 (없으면 이슈 생성)
  → 현재 브랜치 확인 (QA 중이면 같은 브랜치에 계속 커밋)

[원인 분석]
  → debugger 에이전트: 에러 메시지 + 재현 경로 전달
  → 분석 결과 확인 후 수정 파일·라인 특정

[수정]
  → [서비스명]-dev 에이전트에 수정 위임
    (프롬프트: 원인 + 수정 파일 + "수정 범위 최소화")

[검증]
  → 동일 재현 경로 재시도
  → 연관 기능 회귀 확인
  → (FE 프로젝트) 수정된 도메인 FE_*.md 갱신 여부 확인

[세션 종료]
  → doc-writer 에이전트에 HANDOFF 갱신 위임
```

## 스킬 활용 시점

스킬은 에이전트에게 위임하기 전 또는 위임 대신 직접 처리할 때 사용한다.

| 스킬 | 사용 시점 | 패턴 |
|------|----------|------|
| `/project-fix` | QA·버그 이슈 URL/번호가 있을 때 | 이슈 URL 입력 → 서브이슈 생성 + 브랜치 준비 자동화 |
| `/project-pr` | 기능 완료 후 PR 생성 | 현재 브랜치 기준으로 이슈 연결·Co-Authored-By 포함 PR 자동 생성 |
| `/session-close` | 세션 종료 시 | HANDOFF 3종 갱신 + 세션_노트 prepend 자동 처리 |
| `/project-issue` | 새 이슈를 처음부터 만들 때 | 상위+하위 이슈 세트 인터랙티브 생성 |
| `/document-review` | 문서 품질 검증 시 | 구조·연동·완전성 검증 후 이슈 수정 |

**스킬 vs 에이전트 선택 기준:**
- 반복·정형화된 작업 (PR 생성, 이슈 생성, 세션 종료) → **스킬 직접 호출**
- 코드 분석·판단이 필요한 작업 → **에이전트 위임**

## 에이전트 선택 빠른 참조

| 작업 | 에이전트 |
|------|----------|
| 기능 구현, 버그 수정, UI 수정 | `[서비스명]-dev` |
| 문서·HANDOFF 갱신 | `doc-writer` |
| 에러 원인 추적 | `debugger` |
| 코드 리뷰 | `code-reviewer` |
| 리팩토링 | `refactor` |
| 테스트 작성 | `test-writer` |
| 설계 검토 | `architecture` |
| UI 동작 검증 | `[서비스명]-playwright-validator` |
| 크로스 프로젝트·장기 작업 | 마스터 오케스트레이터 에이전트 (`<프로젝트>-master`) |
| 코드베이스 탐색 | `Explore` |

> 마스터 오케스트레이터는 `/project-init`이 코드베이스 분석 결과를 바탕으로 자동 생성하는 프로젝트 메타 에이전트.
> 프로젝트별로 정의되며, 여러 dev 에이전트를 묶어 크로스 프로젝트 작업·장기 Phase 단위 작업을 위임받는다.
