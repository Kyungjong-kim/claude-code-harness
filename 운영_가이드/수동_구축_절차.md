# 수동 구축 절차

## Phase 1 — 사전 준비

```bash
claude --version   # Claude Code CLI
gh --version       # GitHub CLI
git --version
```

```bash
# 프로젝트 구조 파악
find . -maxdepth 3 -not -path "*/node_modules/*" -not -path "*/.git/*" | sort
```

파악할 항목:
- [ ] 언어·프레임워크 (Next.js / FastAPI / Go 등)
- [ ] 모노레포 여부
- [ ] FE / BE / 풀스택 구분
- [ ] 빌드·개발 서버 명령
- [ ] GitHub remote URL

## Phase 2 — 핵심 질문 수집

| 질문 | 예시 |
|------|------|
| Q1. 프로젝트 목적·도메인 | "사용자 채팅 포털", "관리자 대시보드" |
| Q2. 주 작업 영역 | FE / BE / 풀스택 |
| Q3. 브랜치 전략 | "main+develop", "feature 브랜치" |
| Q4. 외부 접근 경로 | 하네스 폴더 경로 또는 "없음" |

## Phase 3 — CLAUDE.md 생성

프로젝트 루트에 `CLAUDE.md` 생성. 최소 포함 항목:

> **docs 경로 결정**: 단일 앱은 `docs/status/`, 모노레포는 `docs/<서비스명>/status/` 사용.
> 아래 예시는 단일 앱 기준. 모노레포이면 경로의 `docs/` 뒤에 서비스명 삽입.

```markdown
# <프로젝트명> — Claude Code 하네스

## 작업 시작 전 필수
- 진입 문서 읽기: `docs/<서비스명>/status/HANDOFF_NOW.md`
- 기존 유사 파일 최소 2개 확인 후 코드 작성

## 브랜치·커밋 규칙
| 항목 | 규칙 |
|------|------|
| 브랜치 | `task/<이슈번호>` 또는 `fix/<이슈번호>` |
| 커밋 접두사 | `[FE]` / `[BE]` / `[공통]` |
| base 브랜치 | `<main 또는 develop>` |

## 빌드·개발 명령
\`\`\`bash
<프로젝트별 명령>
\`\`\`

## 세션 종료 절차
작업 후 `/session-close` 실행.
```

## Phase 4 — HANDOFF 3종 초기화

```bash
# <서비스명>: Q1 답변. 단일 앱이면 그대로 서비스명 사용, 모노레포면 패키지명 사용.
SERVICE=<서비스명>
mkdir -p docs/$SERVICE/{status,plans,history,agent,pages,git-workflow}
```

**docs/\<서비스명\>/status/HANDOFF_NOW.md:**
```markdown
## §1 현재 상태
- **브랜치**: `<기본 브랜치>`
- **이슈**: 없음
- **빌드**: `<빌드 명령>`
- **마지막 작업**: <날짜> — 하네스 초기 구축

## §2 다음 작업
1. 🔴 첫 이슈 생성 후 개발 착수
```

**docs/\<서비스명\>/plans/HANDOFF.md:**
```markdown
## Session Update <날짜>
### 주요 변경
- 하네스 초기 구축 완료
```

**docs/\<서비스명\>/history/세션_노트.md:**
```
> Session note <날짜>: 하네스 초기 구축 완료.
```
