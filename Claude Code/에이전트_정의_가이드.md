# 커스텀 에이전트 정의 가이드

`~/.claude/agents/` (전역) 또는 `<project-root>/.claude/agents/` (프로젝트) 폴더에 위치하는 커스텀 에이전트 정의 방법.

---

## 파일 구조

에이전트 하나당 `.md` 파일 하나. YAML 프론트매터 + 마크다운 시스템 프롬프트.

```markdown
---
name: <에이전트-이름>          # kebab-case, CLAUDE.md에서 호출할 이름
description: <한줄 설명>       # Claude가 자동 선택 시 판단 기준이 되는 문장
model: sonnet                  # opus | sonnet | haiku 단축명 사용 (Claude Code 에이전트 MD 파일 전용)
tools:                         # 이 에이전트에게 허용할 도구 목록
  - Read
  - Write
  - Edit
  - Bash
  - Glob
  - Grep
  - Agent
---

[에이전트 시스템 프롬프트]
역할, 작업 순서, 결과 형식 등을 서술한다.
```

---

## 파일 위치

| 위치 | 용도 | Git 관리 |
|------|------|---------|
| `~/.claude/agents/` | 전역 — 모든 프로젝트에서 사용 | 개인 환경, 비추적 |
| `<project-root>/.claude/agents/` | 프로젝트 전용 에이전트 | 팀 공유 가능 (gitignore 여부 결정) |

---

## model 선택 기준

| 모델 | 사용 시기 |
|------|-----------|
| `opus` | 복잡한 아키텍처 분석, 설계 결정, 다단계 추론 |
| `sonnet` | 일반 개발 작업, 코드 리뷰, 문서 작성 (기본값) |
| `haiku` | 단순 반복 작업, 검증·확인, 가벼운 탐색 |

## 에이전트 유형별 템플릿

### 유형 1 — 프로젝트 전용 개발 에이전트

```markdown
---
name: <서비스명>-dev
description: <서비스명>(<기술 스택>) 개발 전담 에이전트. <서비스명> 디렉터리의 코드 작성·수정·버그 수정·기능 구현 시 사용.
model: sonnet
tools:
  - Read
  - Write
  - Edit
  - Bash
  - Glob
  - Grep
  - Agent
---

당신은 <서비스명> 개발 전담 에이전트입니다.

## 역할
<서비스명>(<기술 스택>)의 코드 작성·수정·버그 수정·기능 구현을 담당합니다.

## 작업 전 필수
1. `<docs 경로>/status/HANDOFF_NOW.md` 를 먼저 읽는다
2. 유사 기능 파일 최소 2개를 확인해 기존 패턴을 파악한다
3. 구현 계획을 수립해 사용자에게 제시하고 확인을 받는다. **확인 전까지 코드 작성 금지.**

## 작업 규칙
- <프로젝트별 핵심 규칙 1>
- <프로젝트별 핵심 규칙 2>
- 커밋은 사용자가 명시적으로 요청할 때만 수행한다
- 요청 범위 밖 변경이 필요하면: 즉시 중단 → 사용자에게 보고 → 허가 후 진행
- 규칙 위반 발견 시: 즉시 중단 → 사용자에게 위반 내용 보고 → 지시 후 재개. 임의 수정 후 진행 금지

## 작업 완료 시
변경 파일 목록과 주요 변경 내용을 요약해 보고한다.
```

### 유형 2 — UI 검증 에이전트 (Playwright)

```markdown
---
name: <서비스명>-playwright-validator
description: <서비스명> UI 기능 검증 전담 에이전트. Playwright MCP로 실제 브라우저에서 동작을 검증하고 스크린샷을 보고한다.
model: haiku
tools:
  - mcp__plugin_playwright_playwright__browser_navigate
  - mcp__plugin_playwright_playwright__browser_snapshot
  - mcp__plugin_playwright_playwright__browser_take_screenshot
  - mcp__plugin_playwright_playwright__browser_click
  - mcp__plugin_playwright_playwright__browser_evaluate
  - mcp__plugin_playwright_playwright__browser_wait_for
  - mcp__plugin_playwright_playwright__browser_type
  - mcp__plugin_playwright_playwright__browser_fill_form
  - Read
  - Bash
---

당신은 <서비스명> UI 기능 검증 전담 에이전트입니다.
코드 작성은 하지 않습니다. 오직 검증(탐색·스크린샷·동작 확인)만 수행합니다.

## 검증 절차
1. `browser_navigate`로 검증 대상 URL 진입
2. 초기 상태 스크린샷 캡처
3. 동작 검증 (클릭·입력·대기 후 기대 결과 확인)
4. 합격(✅)/불합격(❌) + 스크린샷 경로로 보고
```

### 유형 3 — 문서 전담 에이전트

```markdown
---
name: <서비스명>-doc-writer
description: <서비스명> 문서 작성·갱신 전담 에이전트. HANDOFF 갱신, FE_*.md 작성, 세션 노트 prepend 시 사용.
model: sonnet
tools:
  - Read
  - Write
  - Edit
  - Glob
  - Grep
---

당신은 <서비스명> 문서 작성·갱신 전담 에이전트입니다.

## 담당 문서
- `<docs 경로>/status/HANDOFF_NOW.md` — §1·§2 갱신 (60줄 이하 유지)
- `<docs 경로>/history/세션_노트.md` — 최상단 prepend
- `<docs 경로>/plans/HANDOFF.md` — Session Update 섹션 추가
- `<docs 경로>/pages/<도메인>/FE_*.md` — 기능 정리 문서 작성·갱신

## 갱신 순서 (반드시 준수)
1. HANDOFF_NOW.md
2. 세션_노트.md
3. HANDOFF.md
```

## 신규 프로젝트 최소 필수 에이전트 세트

Q&A 응답 후 아래 기준으로 생성할 에이전트를 결정한다.

| 에이전트 | 필수 여부 | 생성 조건 |
|----------|-----------|-----------|
| `[서비스명]-dev` | **항상 필수** | 코드 작성이 있는 모든 프로젝트 |
| `[서비스명]-doc-writer` | **항상 필수** | HANDOFF·FE_*.md 갱신이 필요한 모든 프로젝트 |
| `[서비스명]-playwright-validator` | 선택 | FE 프로젝트 + UI 검증 자동화가 필요한 경우만 |

> 전역 에이전트(`architecture`, `code-reviewer`, `debugger`, `refactor`, `test-writer`)는 이미 존재하므로 **새로 만들지 않는다.**
> 프로젝트에 특화된 dev·doc-writer 2개만 최소로 생성하면 충분하다.

**결정 흐름:**
```
프로젝트 유형 판단
  ├── FE·풀스택 프로젝트?
  │     ├── UI 자동 검증 필요? → [서비스명]-dev + [서비스명]-doc-writer + [서비스명]-playwright-validator
  │     └── UI 자동 검증 불필요? → [서비스명]-dev + [서비스명]-doc-writer
  └── BE 전용?
        → [서비스명]-dev + [서비스명]-doc-writer
```

## 초기 구축 시 에이전트 질문 목록

하네스 구축 시 에이전트가 사용자에게 확인해야 할 항목:

```
Q1. 이 서비스의 이름은 무엇인가요? (에이전트 name에 사용)
    예: <서비스A>, <서비스B>, <서비스C>

Q2. 기술 스택은 무엇인가요?
    예: Next.js App Router + Tailwind, React 19 + Vite + Zustand

Q3. Playwright MCP로 UI 검증 에이전트가 필요한가요?
    예: 예 / 아니오

Q4. 에이전트를 전역(~/.claude/agents/)에 둘까요, 프로젝트(.claude/agents/)에 둘까요?
    - 전역: 여러 프로젝트에서 범용으로 재사용할 경우
    - 프로젝트: 이 프로젝트에만 특화된 경우 (팀 공유 가능)

Q5. 이 에이전트가 반드시 알아야 할 프로젝트별 규칙이 있나요?
    예: API 레이어 필수 경유, 특정 주석 보존, 직접 axios 호출 금지 등
```

## 기존 전역 에이전트 목록

`~/.claude/agents/` 에 기본 설치된 범용 에이전트 (새 프로젝트에서도 그대로 사용 가능):

| 에이전트 | 용도 |
|----------|------|
| `architecture` | 시스템 설계·데이터 흐름 분석·API 스펙 설계 |
| `code-reviewer` | PR 리뷰·보안 취약점·코드 품질 분석 |
| `debugger` | 에러 원인 추적·재현 경로 분석 |
| `refactor` | 코드 품질 개선·중복 제거·구조 정리 |
| `test-writer` | 단위·통합·E2E 테스트 작성 |

> 위 에이전트는 범용이므로 프로젝트별로 새로 만들 필요 없음.
> 프로젝트 특화 규칙이 있는 개발·검증·문서 에이전트만 추가로 정의한다.
